# Assignment 05

A TypeScript monorepo using pnpm workspaces.

## Requirements

- Node.js 22.12+ (Node.js 24 LTS recommended)
- pnpm 11.24.0 (the version pinned in `package.json`)

## Start

```sh
pnpm install
pnpm db:up
pnpm db:migrate
pnpm dev
```

Copy `.env.example` to `.env` before running the database commands. The development compose file starts PostgreSQL 16 on port 5432 by default.

- Web: http://localhost:5173
- API: http://localhost:3000

Vite proxies `/api` requests to the API during development. Production hosting must route `/api` to the API separately.

## Workspace

```text
apps/
  api/                  Hono + Zod + @hono/zod-validator, running on Node.js
    src/app.ts          Routes (separate from the server for testing)
    src/index.ts        Server entry point
  web/                  React + Vite + TanStack Router + Tailwind CSS v4
    src/routes/         File-based routes
    src/routeTree.gen.ts Generated by the TanStack Vite plugin; do not edit
packages/
  db/                    PostgreSQL client and raw SQL migrations
    migrations/          Ordered, checksum-verified SQL migrations
  agents/
    index.ts            Public exports for @repo/agents
    src/agent.ts        runAgent(options)
    src/models.ts       Devscale model client (deepseek-v4.1-flash by default)
    src/instruction.ts  Base system prompt
    src/context/        Static Anvia Document context
    src/tools/          Tavily web search and webpage reading
```

Add route files under `apps/web/src/routes/`; Vite regenerates the route tree when starting development or building. Keep `routeTree.gen.ts` in version control so typechecking also works before starting Vite.

## Commands

```sh
pnpm dev        # Run API and web together
pnpm build      # Build all packages into their respective dist/ directories
pnpm typecheck  # Typecheck all packages
pnpm db:up      # Start the PostgreSQL 16 development container
pnpm db:migrate # Apply pending raw SQL migrations
pnpm db:down    # Stop the development database
```

Run a single app:

```sh
pnpm --filter @repo/api dev
pnpm --filter @repo/web dev
```

After building, run the API with `pnpm --filter @repo/api start`. Use `pnpm --filter @repo/web preview` to preview the web build locally (not a production server).

## Example API requests

```sh
curl http://localhost:3000/api/health

curl http://localhost:3000/api/hello \
  -H 'Content-Type: application/json' \
  -d '{"name":"World"}'
```

`POST /api/hello` returns HTTP 400 when `name` is missing, blank, or not a string.

## Using the agents package

The private `@repo/agents` package uses `@anvia/core`, `@anvia/openai`, `@anvia/lens`, and `@tavily/core`.

Copy `.env.example` to `.env` and fill in `OPENAI_API_KEY` (your Devscale gateway key), `TAVILY_API_KEY`, and the `ANVIA_LENS_*` project credentials. The model client defaults to `https://gateway.devscale.id/v1`; `OPENAI_BASE_URL` can override it. The agents package loads `.env` with Node.js when the file exists in the current working directory. Lens tracing is disabled when all three connection variables are absent. Traces and eval reports include payloads, so do not enable this configuration for sensitive production data without reviewing redaction, access, and retention.

Run from the repository root:

```sh
pnpm --filter @repo/agents build
node --env-file=.env --input-type=module <<'JS'
import { runAgent } from './packages/agents/dist/index.js'

const stream = runAgent({
  messages: [{ role: 'user', content: 'What is this project built with?' }],
})
for await (const text of stream.textStream) {
  process.stdout.write(text)
}
process.stdout.write('\n')
JS
```

`runAgent` accepts either `messages` for a stateless run or `prompt` plus `session` for a memory-backed run, along with optional `abortSignal`, `modelId`, and `memoryStore`. The API supplies the PostgreSQL memory store and a browser-scoped session. It defaults to `deepseek-v4.1-flash`, includes the base prompt and static document, attaches the Lens observer, retries transient provider failures, and limits the run to 25 turns. The exported `search-web` and `read-webpage` tools are not attached by default because the Devscale gateway's DeepSeek streaming responses currently emit tool calls that are incompatible with Anvia's OpenAI protocol validation. It returns `agent.stream()` directly: consume `stream.textStream` or `stream.events`, and await `stream.result` for the final outcome. `getModel(modelId?)`, `BASE_INSTRUCTION`, `document`, `lens`, `lensTracing`, `lensEvalReporter`, `webSearchTool` (`search-web`), and `readWebpageTool` (`read-webpage`) are also exported. Each `runEvalCli()` uses the Lens eval reporter and closes Lens after reporting. Long-running servers should call `lens.close()` during graceful shutdown; other short-lived scripts should call `lens.flush()` after their final run.

Chat conversations are persisted in PostgreSQL. The web app assigns anonymous browser and conversation UUIDs, sends them to the API, restores the active conversation after reload, and lists saved conversations in the sidebar. The API exposes `GET /api/conversations` and `GET /api/conversations/:ref`; both require the browser identity headers used by the web client.

To use it from an app, link the workspace package:

```sh
pnpm --filter @repo/api add @repo/agents@workspace:*
```

Import from `@repo/agents` on the server only; never bundle the package or API keys into the web client. The package exports compiled JavaScript and TypeScript declarations from `dist/`; rebuild it after changing its source.
